# 开发构建与调试验证

## 构建环境

项目使用 SwiftPM，无需 Xcode 工程。开发环境需要 macOS 14+、Swift 5.10+ 和可用的 macOS SDK；依赖配置见 [Package.swift](../../Package.swift)。以下命令均在仓库根目录执行。

## 常用命令

项目仅保留 `build_and_run.sh`，统一构建、运行、调试、校验和发布。

| 命令 | 用途 |
| --- | --- |
| `./script/build_and_run.sh` | 构建、签名并启动 Release 应用 |
| `./script/build_and_run.sh --debug-run` | 构建并启动 Debug 应用 |
| `./script/build_and_run.sh --debug` | 使用 LLDB 调试 |
| `./script/build_and_run.sh --verify` | 临时签名包自检，不替换正在运行的应用 |
| `./script/build_and_run.sh --ui-preview` | 隔离临时数据预览，不加载正式 BOSS 会话 |
| `./script/build_and_run.sh --logs` | 启动并查看进程日志 |
| `./script/build_and_run.sh --telemetry` | 启动并查看应用子系统日志 |

构建产物为 `dist/BossPilot.app`，使用本地 ad-hoc 签名，不代表 Apple 公证发行包。上述本地运行与调试入口会更新应用包并关闭旧实例，`--verify` 和 `--release` 不关闭旧实例，执行前保存编辑内容。具体行为以[构建脚本](../../script/build_and_run.sh)为准。

## 仓库同步

本地 `main` 从 GitHub 拉取，`origin` 同时配置 GitHub 和 Gitea 两个推送地址。首次克隆后执行一次：

```bash
git remote set-url origin https://github.com/Logistic98/boss-pilot.git
git config --replace-all remote.origin.pushurl https://github.com/Logistic98/boss-pilot.git
git remote set-url --add --push origin https://gitea.imiao.top/yoyo/boss-pilot.git
```

日常执行 `git push` 或 `git push origin main` 即可依次推送两个仓库。两端需要分别具备写入权限；推送不具备跨仓库原子性，若一端失败，处理该端错误后重试，已同步的一端会显示无需更新。推送地址保存在本地 `.git/config`，不会随克隆继承。

## GitHub Release

发布需要 Python 3.9+，通过统一脚本的 `--release` 参数执行，不直接压缩日常运行的 `dist/BossPilot.app`：

```bash
./script/build_and_run.sh --release v1.0.0
```

脚本从源码全新构建当前 Mac 架构的 Release 应用，重写编译路径、移除调试信息，校验文件白名单和常见敏感信息，再运行隔离自检。生成的 ZIP 和 SHA-256 校验和位于 `dist/releases/`，包含 MIT 许可证，不打包账号、简历、Cookie、授权文件或日志，也不停止正在运行的应用。

发布校验及规则反例检查已内置，无需额外脚本。检查已有发布包：

```bash
./script/build_and_run.sh --verify dist/releases/BossPilot-v1.0.0-macos-arm64.zip
```

自动上传需先安装 GitHub CLI 并执行 `gh auth login`，提交代码并将对应版本标签推送到 GitHub，然后执行：

```bash
git tag v1.0.0
git push origin main v1.0.0
./script/build_and_run.sh --release v1.0.0 --publish
```

可用 `--repo OWNER/REPO` 指定仓库。上传前要求工作区干净且远端标签指向当前提交；脚本不会自动提交、推送源码或覆盖已有 Release。版本格式为 `v主版本.次版本.修订号`，同时写入应用版本信息。Release 创建和标签校验使用 [GitHub CLI](https://cli.github.com/manual/gh_release_create)。

GitHub 与 Gitea 使用相同版本标签，并上传同一次构建生成的 ZIP 和 SHA-256 校验文件。`--publish` 仅上传 GitHub；Gitea 发布需在[发布页面](https://gitea.imiao.top/yoyo/boss-pilot/releases)选择对应标签，填写版本说明并上传相同文件，保持两端版本与校验值一致。

发布包使用 ad-hoc 签名，未做 Apple 公证。macOS 默认 Gatekeeper 策略下的正式发行还需要 [Developer ID 签名与公证](https://developer.apple.com/developer-id/)。敏感信息规则是发布前检查，不能替代源码审查。

## 验证范围

| 变更 | 验证重点 |
| --- | --- |
| 文档与配图 | 链接、标题锚点、代码块、图片文字与功能一致性 |
| 业务规则、账号生命周期、投递与持久化 | 隔离自检及受影响的状态路径 |
| 界面布局与交互 | 隔离 UI 预览，并按影响范围补充实际交互验证 |
| 平台接入 | 正式账号流程与接口兼容性，执行前确认外部读写影响 |

隔离自检验证本地规则，UI 预览验证界面，二者均不能替代实际登录、同步和投递验证。

## 正式账号诊断

脚本保留 `--greeting-delivery`、`--greeting-confirmation` 和 `--greeting-reset-confirmed-absent` 入口。这些入口连接正式账号，不属于离线自检，须遵循程序的显式授权与结果核对要求。

## 代码与文档维护

源码直接放在 `Sources/` 下，按职责划分为 `App/`、`Controllers/` 等目录，不再嵌套产品名称目录。SwiftPM 的源码路径由 `Package.swift` 指定，构建与打包脚本统一读取该配置。入口见[系统架构与技术选型](../架构设计/系统架构与技术选型.md#源码导航)。注释使用简洁中文，接口名称保留原文；`///` 说明调用约束、状态含义或安全边界，`//` 解释代码不能直接表达的原因。已知限制用 `shortcut:` 标注限制与替换条件。

README 保留产品定位、核心能力、架构和快速开始；操作、规则、隐私与开发细节写入对应主题文档。配置值以实现为准，避免多处完整复制。新增或移动文档时，同步更新根 README 的“项目文档”并检查相对链接。

配图中的功能示意应明确标注；自动沟通与自动投递的文案需与实际发送范围、交换条件保持一致。
