# 自动沟通与简历投递

## 执行范围

自动任务依次推进岗位检索、详情补全、匹配评估、预设招呼语开聊、消息同步与附件简历投递。沟通草稿仅供本地参考，不自动发送任意文字回复。手动刷新只同步数据，不触发外发。完整手动同步期间会暂停自动任务，完成后恢复；这段时间也计入实际运行耗时。

## 启动条件与默认配置

从运行设置启动任务，需要已导入本地简历、至少一个通过登录和本人验证检查的可运行账号，且未处于风险冷却期。启用岗位检索时需保存求职条件；岗位检索与消息同步至少启用一项。简历投递依赖消息同步。

| 配置 | 默认值 | 可设置范围 |
| --- | --- | --- |
| 后台任务 | 未启动 | 手动启动或停止 |
| 岗位检索 | 开启 | 以运行设置为准 |
| 消息同步 | 开启 | 开启或关闭 |
| 自动简历投递 | 关闭 | 满足条件后开启 |
| 候选补货间隔 | 每批完成后至少 90 秒 | 快速开聊时两批开始时间至少间隔 10 秒 |
| 消息同步间隔 | 60 分钟 | 30–180 分钟 |
| 每账号每日开聊上限 | 150 | 1–150 |
| 同账号相邻开聊间隔 | 180 秒 | 35–1800 秒 |

在「运行设置 → 开聊节奏」选择「使用快速开聊（35 秒）」即可启用，旧的更短间隔会自动收紧到 35 秒。间隔低于 180 秒时，每个账号独立安排开聊、补货和消息同步。所有账号继续共用进程级请求限速，快速档读取请求至少间隔 3 秒。每账号两小时完成 150 次是调度目标，实际数量取决于合格岗位、平台响应和当日剩余额度。

快速档每轮消息同步最多轮转两个会话，手动完整同步仍保留原有批量。自动附件投递关闭时，自动同步不重复查询附件交换统计。登录态失效仅暂停对应账号，不影响其他账号；收到开聊提醒、明确限流或安全验证时，仅暂停异常账号并取消其排队请求，不能持续换岗重试。

## 岗位检索与自动开聊

岗位详情逐条保存，后续同步复用已有信息并补齐缺失项。缺少完整描述的岗位不能自动开聊。

待开聊候选不足 8 个时，自动任务按表中的间隔补货。优先补齐最近 24 小时内搜到的缓存岗位，详情积压处理完后继续检索。快速开聊会在两次发送之间补货，每批检索一组条件，轮完当前页的所有条件后翻页。库存充足或当日额度用完时暂停补货。每批最多读取 4 个详情。平台明确返回职位不存在时，停止重读该岗位的旧路由。其他详情失败保留 15 分钟退避。

列表已有明确排除项、薪资不重合或严格限定城市不符时，不再为其读取详情。未知字段与缺少必需关键词仍留待详情核实。快速档优先补齐同等条件下标题命中求职方向的岗位，队列为空时定期轮到新的检索结果。详情取得后立即进行本地评估，自动批次可提前结束，将已就绪的候选交给开聊流程。

求职要求中标明的「岗位」方向优先用于检索和评估。检索使用方向关键词，例如「AI应用研发工程师」检索「AI应用」，岗位评估仍按完整方向与严格条件判断。每天从优先方向、城市的第一页开始，当天保留翻页进度。详情缺少岗位名称时，保留列表中的岗位名。再次搜到旧岗位时，使用新列表的名称和缓存的职位描述重新判断匹配度。

匹配与最终发送前均检查明确的排除条件。外发前重新核对最新求职要求、账号状态、额度和防重记录，通过后使用对应 BOSS 账号的预设招呼语。

开聊尝试按身份与岗位去重核算，手动沟通和工具尝试均纳入额度；结果未知的尝试也占用额度。删除本地记录或重启不会清除限制。

快速档最多提前 8 秒只读核对额度，开聊名额登记和实际消息提交各自受发送间隔约束。已就绪的开聊与回读核验优先取得请求时隙，未来的开聊时隙不阻塞补货。消息提交后最多等待 1 秒实时 ACK，随后回读完整会话确认送达，只有服务端 MID 校验通过才计为成功。新会话优先等待页面缓存更新，必要时才重新加载官方聊天页。若仍无法确认，该账号从上次消息提交起至少等待 90 秒再开聊。

## 两类简历的区别

| 简历 | 来源 | 用途 |
| --- | --- | --- |
| 本地分析简历 | 求职偏好中导入的 PDF、TXT 或 Markdown | 提取正文、生成画像与岗位筛选 |
| 对外投递附件 | 对应 BOSS 账号中唯一可用的附件简历 | 按交换条件发送给招聘方 |

投递前应在 BOSS 官方端核对附件版本。更新本地分析简历不会同步替换平台附件；缺少唯一可用附件时无法按此流程自动投递。

## 简历交换与确认

原生索要卡片与普通文字同意进入不同的交换流程。创建简历请求后可能仍需招聘方确认；明确拒绝会被过滤，需要判断的情况转为待办。

| 状态语义 | 含义与处理 |
| --- | --- |
| 请求已创建 | 已发起交换流程，可能仍待招聘方确认 |
| 处理中或待确认 | 核对平台回执与历史，不重复发送 |
| 已交换 | 平台接受附件发送，或完整历史确认附件已发出 |
| 结果未知 | 尚不能确定结果，只核对历史，不自动重发 |

此表解释业务语义，实际界面标签以当前页面为准。交换时间取发送或接受时间，不取后续查看时间。同一会话已有进行中、已确认或结果未知的投递时，不重复发送；后续处理与待确认回读分别按 3 分钟、5 分钟调度。

## 运行保护

外发前必须先成功持久化安全记录；保存失败则停止对应写入。普通状态保存、文本提取与 Codex 分析在后台执行。

退出时立即取消后台任务，不等待平台响应；仅短暂等待取消回调，再保存最新状态。已进入发送阶段但结果未确认的投递保留为结果未知，下一次启动不会自动重发；尚未提交的附件准备可重试。

明确限流、拒绝访问、安全验证或开聊提醒会暂停对应账号，其他账号继续独立运行。暂停状态在重启后保留，不设置固定 24 小时全局锁定；在官方页面检查后，可从“账号管理”点击“我已检查，恢复此账号”。所有账号都暂停时停止后台任务，手动恢复账号不会自动启动已停止的后台。普通超时和普通业务拒绝仍按单次请求处理。

节奏控制与防重机制不能保证账号免受平台限制。异常恢复步骤见[使用指南与常见问题](../使用指南/使用指南与常见问题.md#常见问题)。
